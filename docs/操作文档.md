# 个人博客系统 - 操作文档

> 本文档对应 2026-08-05 版本（v2.6.31）的当前实现，请以实际代码为准。

## 快速开始

### 本地运行

项目为纯前端静态站点，无需构建，任选一种方式：

```bash
# 方式一：Node.js
npm install -g http-server
http-server -p 8080

# 方式二：Python
python -m http.server 8080

# 方式三：VS Code
# 安装 Live Server 插件，右键 index.html -> Open with Live Server
```

> 提示：直接双击打开 `index.html` 也能运行，但建议使用本地服务器，避免个别浏览器对 `fetch` 本地文件的限制。

### 部署到 GitHub Pages

仓库根目录已包含 `.nojekyll` 与 `CNAME`（自定义域名 `ravennull.work`），部署步骤如下：

1. 将代码推送到 GitHub 仓库的 `main` 分支
2. 仓库 Settings -> Pages，Source 选择 "Deploy from a branch"，分支选 `main`、目录 `/ (root)`
3. 点击 Save，等待数分钟部署完成
4. 通过域名或 `https://你的用户名.github.io/仓库名/` 访问；`feed.xml` 提供 RSS 订阅

> 部署后样式/功能异常时，先强制刷新（Ctrl+F5）清掉浏览器缓存，见「常见问题」。

## 添加文章

### 1. 创建 Markdown 文件

在 `posts/` 文件夹中新建 `.md` 文件，例如 `my-new-post.md`。

### 2. 编写 Frontmatter

文件开头必须包含 Frontmatter：

```yaml
---
title: 我的新文章
date: 2026-08-05
tags: [技术, 生活]
author: 渡鸦NULL
excerpt: 这是文章的摘要，会显示在首页卡片上。
image: images/BG/01_BG.webp
update: 2026-08-06
---
```

字段说明：

| 字段 | 必填 | 说明 | 示例 |
|------|------|------|------|
| title | 是 | 文章标题 | `我的新文章` |
| date | 是 | 发布日期 | `2026-08-05` |
| tags | 是 | 标签数组（也支持逗号分隔的字符串） | `[技术, AI]` |
| author | 否 | 作者名（决定卡片头像） | `渡鸦NULL` / `AI` |
| excerpt | 否 | 文章摘要，不填则自动截取正文 | `这是摘要...` |
| image | 否 | 封面图片路径，不填则从 `bgImages` 随机取 | `images/BG/01_BG.webp` |
| update | 否 | 更新日期，文章页会显示「更新于」 | `2026-08-06` |

> 头像规则：`渡鸦NULL` → `images/TX/01_TX.webp`；`AI` → `02_TX.webp`；其他 → `03_TX.webp`。

### 3. 编写正文

使用标准 Markdown 语法。代码块指定语言可高亮：

````markdown
# 一级标题

## 二级标题

正文内容...

- 列表项1
- 列表项2

**粗体** 和 *斜体* 以及 ==高亮文字==

> 这是引用内容

[链接文字](https://example.com)

![图片描述](images/assets/01-blog-usage-guide/1.jpg)

```javascript
console.log('Hello World!');
```
````

### 4. 更新 manifest.json

打开 `posts/manifest.json`，将新文件名加入数组（文章按 `date` 倒序展示，文件顺序无关）：

```json
[
    "01-blog-usage-guide.md",
    "my-new-post.md"
]
```

### 5. 刷新页面

刷新首页即可看到新文章（发布 3 天内带 NEW 徽标）。

## 使用图片

### 添加图片

1. 将图片放入项目根目录的 `images/` 文件夹（建议按文章建子目录，如 `images/assets/文章名/`）
2. 在 Markdown 中引用：

```markdown
![图片说明文字](images/assets/01-blog-usage-guide/1.jpg)
```

> 路径相对于站点根目录，与文章所在 `posts/` 无关，无需 `../` 前缀。

### 图片功能

- **说明文字**：`alt` 文本会自动显示在图片下方作为说明
- **灯箱放大**：点击图片可放大查看，见「图片灯箱」
- **懒加载**：图片默认懒加载，提升页面速度

### 路径格式

```markdown
# 本地图片（推荐，放 images/ 下）
![图片](images/photo.jpg)

# 支持多层子目录
![图片](images/2026/blog/cover.png)

# 外部 URL
![图片](https://example.com/image.jpg)
```

## 图库

图库视图展示 `images/R-N-picture/` 文件夹中的全部图片。

### 添加图片到图库

1. 将图片放入 `images/R-N-picture/`（支持 jpg/png/webp/gif 等格式）
2. 运行命令重新生成图库清单：

```bash
node scripts/build-gallery.js
```

3. 提交时把图片文件与生成的 `manifest.json` 一并提交
4. 刷新页面，图库自动显示新图片，无需改动其他代码

> 原理：脚本扫描目录生成 `images/R-N-picture/manifest.json`，前端读取该清单渲染。**只放图片、不跑脚本，图库不会更新。**

## 资讯

「我的」视图中的资讯推荐模块展示 `data/recommendations.json` 中的精选网站新闻资讯。

### 添加 / 修改 / 下架资讯

直接编辑 `data/recommendations.json`，每条记录字段：

| 字段 | 必填 | 说明 |
|------|------|------|
| `title` / `url` | ✅ | 新闻标题与原文链接（http/https） |
| `source` | ✅ | 来源网站 / 媒体名称 |
| `category` | 推荐 | 资讯分类（如 科技 / 开发 / AI） |
| `date` | 推荐 | 发布日期，格式 YYYY-MM-DD |
| `summary` | 可选 | 一句话摘要 |

改完提交推送即可。

### 校验资讯数据

```bash
node scripts/check-recommendations.js            # 字段合法性校验
node scripts/check-recommendations.js --check    # 追加外链健康检查
```

> 校验脚本只做质量把关，可选用；`--check` 会逐条请求原文链接，报告失效项。

## AI智能助手

位于**文章页**右下角的悬浮按钮（首页不含）。基于智谱 GLM-4 接口。

### 配置

打开 `js/chat.js`，修改 `config`：

```javascript
config: {
    apiUrl: 'https://open.bigmodel.cn/api/paas/v4/chat/completions',
    apiKey: 'YOUR_API_KEY_HERE',  // 替换为你的智谱 API Key
    model: 'glm-4-flash',         // 模型名，可切换
    maxTokens: 2048,              // 最大输出 token 数
    temperature: 0.7              // 温度（随机性）
}
```

API Key 获取地址：https://open.bigmodel.cn/

### 使用方法

1. 点击右下角聊天图标（或文章页左侧栏 💬 按钮）打开对话窗口
2. 底部输入框输入问题，回车或点击发送
3. 回复为**流式输出**，生成中发送按钮变为「停止」，点击可停止
4. AI 回复支持 Markdown 渲染与代码高亮，回复下方提供「复制 / 重新生成」

### 功能特性

- **多会话管理**：点击会话按钮可新建 / 切换 / 删除会话，历史自动保存（localStorage）
- **划词问答**：在文章正文中选中文字，弹出「解释 / 翻译 / 润色」气泡，一键调用 AI
- **快捷指令**：输入 `/` 唤起菜单（解释 / 翻译 / 润色 / 总结 / 写代码），点击自动填入提示词
- **字数统计**：输入框实时显示字数，上限 2000
- **未读角标**：窗口关闭时收到回复，悬浮按钮显示未读数量
- **窗口位置记忆**：可拖拽移动、调整大小，位置与尺寸自动保存（移动端不启用）
- **友好错误提示**：限流（429）、API 认证失败（401/403）等都有明确提示

### 修改助手人格

`js/chat.js` 中的 `systemPrompt` 为系统提示词，可自定义管理员人设与回复风格。

## 常见问题

### Q: 文章不显示？

1. 文件是否在 `posts/` 文件夹、扩展名为 `.md`
2. 文件名是否加入了 `posts/manifest.json`
3. Frontmatter 格式是否正确（`title`、`date`、`tags` 必填）
4. 是否刷新了页面

### Q: 图库不更新？

图库列表由 `images/R-N-picture/manifest.json` 决定，**放入图片后必须运行**：

```bash
node scripts/build-gallery.js
```

并将图片与 `manifest.json` 一起提交。

### Q: 样式不生效 / 一直是旧版本？

1. 强制刷新：`Ctrl+F5`（Mac：`Cmd+Shift+R`）
2. 修改资源后更新链接的 `?v=` 版本号（`index.html` / `article.html` 中的 `?v=2.6.44`）
3. GitHub Pages 部署需等待几分钟

### Q: AI 助手无法使用？

1. 是否在 `js/chat.js` 中配置了正确的 API Key
2. 错误提示若为「API 认证失败」→ Key 无效或过期，重新生成
3. 「请求过于频繁」→ 接口限流，稍后再试
4. 网络是否正常，检查浏览器控制台（F12）错误信息

### Q: 图片灯箱不工作？

1. 图片本身是否正常加载（是否 404）
2. 是否禁用了 JavaScript
3. 检查控制台是否有脚本报错

### Q: 主题切换无效？

1. 是否清除了浏览器缓存
2. 是否禁用了 JavaScript
3. 检查 `js/theme.js` 语法是否正确

### Q: 文章页无法滚动？

滚动区域为页面主体而非首页的 `#scrollArea`；若页面整体锁死，强制刷新一次（历史版本曾出现 `body { overflow: hidden }` 误伤，当前已修复）。

## 高级用法

### 1. 自定义域名

仓库已含 `CNAME`（内容为 `ravennull.work`）。更换域名时：

1. 修改 `CNAME` 文件内容
2. 在域名服务商配置 CNAME 记录指向 `你的用户名.github.io`

### 2. GitHub Actions 自动部署

未内置 workflow，可自行创建 `.github/workflows/deploy.yml`，推送时自动部署：

```yaml
name: Deploy to GitHub Pages
on:
  push:
    branches: [ main ]
permissions:
  contents: read
  pages: write
  id-token: write
jobs:
  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/configure-pages@v4
      - uses: actions/upload-pages-artifact@v3
        with:
          path: '.'
      - id: deployment
        uses: actions/deploy-pages@v4
```

同时需在 Settings -> Pages 将 Source 改为 "GitHub Actions"。

### 3. 批量添加文章

1. 将所有 `.md` 文件放入 `posts/`
2. 更新 `posts/manifest.json`
3. 提交并推送

### 5. 文章缓存机制

首页文章元数据缓存在 `sessionStorage`（键 `blog-posts-data-v3`），包含版本号。删除该键或换浏览器即可强制重新加载；图库清单缓存在内存中，刷新页面即重新读取。

## 维护建议

### 定期备份

```bash
git pull origin main
```

建议养成「写完文章即提交」的习惯：

```bash
git add posts/ images/
git commit -m "新增文章/图片"
git push origin main
```

### 清理缓存

遇到异常时依次尝试：

1. 强制刷新 `Ctrl+F5`
2. 清空浏览器 localStorage / sessionStorage
3. 清空浏览器缓存

### 图片体积控制

- 优先使用 webp 格式（封面 `images/BG/` 均为 webp）
- 图库图片与文章图片控制在合理体积，避免拖慢首屏
