# 04 · 写作规范

> 人和 AI 都要遵守。AI 专用流程见 [05-AI-写文章指南](./05-AI-写文章指南.md)，可直接抄的指令见 [06-提示词模板](./06-提示词模板.md)。
> 本规范描述的是**这个博客的现状**：文章经后台保存、存于 Netlify Blobs、以 Markdown 落盘。

---

## 一、一篇文章由五样东西组成

| 字段 | 必填 | 说明 |
|------|------|------|
| 标题 | 是 | 说清「讲什么」，15–30 字为宜，不加书名号与感叹号 |
| 摘要 | 建议 | 1–2 句，卡片上就靠它决定读者点不点 |
| 标签 | 是 | 2–4 个，优先复用已有标签，别造同义词 |
| 封面 | 建议 | 从图库选；留空则保存时随机挑一张 |
| 正文 | 是 | Markdown，结构见下 |

标签的作用不只是分类——它决定首页筛选、热门标签、相关推荐。**同一个概念只用一个标签**，比如已经在用「前端」就别再新增「前端开发」。

---

## 二、正文结构

推荐骨架（不必逐条照搬，但顺序别乱）：

```
导语：一段话说清「这篇解决什么问题 / 我会得到什么」
├─ H2 第一个主体：概念 / 背景 / 为什么
├─ H2 第二个主体：怎么做（步骤、代码、对比）
├─ H2 第三个主体：坑与边界（失败案例、注意事项）
└─ 收尾：一句话总结 + 下一步指向
```

硬性要求：

- **正文从 `##` 开始**。`#` 一级标题由「标题」字段生成，正文再写 H1 会让目录出现重复项。
- 小节最多到 `####`，再深说明该拆文章了。
- 每个 H2 下面至少 2 段，否则不如合并。
- 段落 2–5 句，一段只说一件事。
- 长文（>3000 字）在开头给一句「读完你会知道什么」。

## 三、Markdown 支持情况

| 格式 | 写法 | 备注 |
|------|------|------|
| 二级～四级标题 | `##` `###` `####` | 会进左侧目录 |
| 加粗 / 斜体 | `**文字**` / `*文字*` | |
| 删除线 | `~~文字~~` | |
| 行内代码 | `` `code` `` | |
| 高亮 | `==文字==` | 本站扩展语法，慎用，一段最多一处 |
| 列表 | `- 项` / `1. 项` | |
| 任务列表 | `- [ ]` / `- [x]` | |
| 链接 | `[文字](url)` | 站外链接请带 `https://` |
| 图片 | `![图注](url)` | alt 会显示为图注 |
| 代码块 | ` ```javascript ` | **必须标语言**，否则不高亮 |
| 引用 | `> 文字` | 可一键复制，适合放结论或原文摘录 |
| 表格 | GFM 表格 | 列数别超过 5 列，移动端会挤 |
| 脚注 / 定义列表 | — | 不支持 |

**不要再用的写法：**

- ` ```embed board:xxx ` / ` ```embed map:yyy ` ——该语法**已移除**，现在按普通代码块渲染。
  白板、思维导图、节点图是独立的文章形态（`type` 字段），不是正文里的嵌入块。
- 手写 HTML 标签 —— 不可靠，可能被过滤掉。

## 四、表达风格

### 语言

- 简体中文，用全角标点。中英文之间留一个空格：`用 Netlify Blobs 存文章`。
- 技术术语保留英文原形（`API`、`Blobs`、`Markdown`），不要硬译成「应用程序接口」。
- 首次出现的缩写给一次全称，之后直接用缩写。
- 人称统一用「我」（作者视角）或直接陈述，不要一会儿「我们」一会儿「你」。

### 语气

- 直接、具体、可执行。避免「众所周知」「显而易见」「赋能」「闭环」这类空词。
- 允许多一点个人判断（「我更倾向 A，因为 B」），但不许武断。
- 不用感叹号堆气势；一段最多一个冒号。

### 表情符号：不用

这是这个站的既定规范，来源是站内提示词（`public/js/chat.js`、`netlify/functions/admin.ts`）：

- **正文、标题、摘要里一律不用 Emoji**
- 确实需要语气时，最多用一个颜文字（如 `(￣ω￣)`），且**技术内容里不用**
- 这一点对 AI 是硬约束，见 [05-AI-写文章指南](./05-AI-写文章指南.md)

### 长度

| 类型 | 建议字数 |
|------|----------|
| 短记 / 随笔 | 800–1500 |
| 常规技术文 | 2000–4000 |
| 深度长文 | 4000–10000（超过 30000 会自动分章） |

宁短勿水。删掉不承载信息的段落比凑字数强。

## 五、代码块

````markdown
```javascript
const store = getBlobStore("blog-articles");
const article = await store.get(id);
```
````

- 一定标语言：`javascript` / `typescript` / `bash` / `json` / `yaml` / `html` / `css` / `python`
- 代码里只放能跑的最小片段，省略的部分用注释 `// ...` 明示
- 命令用 `bash`，Windows 专属命令要说明是 PowerShell
- 不要在代码块里塞大段报错日志，截关键几行，其余用文字概括

---

## 六、图片

- 优先从图库选（自动 WebP、统一尺寸），其次外链
- `![图注](地址)` 的图注要写清「图里是什么」，不要写「图片」
- 一张图配一段说明文字，别让图自己说话
- 截图裁掉无关区域再传，正文宽度有限

---

## 七、发布前自检

- [ ] 正文没有 `#` 一级标题
- [ ] 每个代码块都标了语言
- [ ] 没有 Emoji
- [ ] 没有 `TODO`、`（此处补充）`、`Lorem` 之类占位
- [ ] 标签 2–4 个，且是已有标签
- [ ] 摘要单独成句，脱离正文也能看懂
- [ ] 目录层级连贯（没有从 H2 直接跳 H4）
- [ ] 声称的事实有依据；不确定的地方写明了「待核实」
