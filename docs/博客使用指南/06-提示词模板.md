# 06 · 提示词模板

---

## 一、系统提示词（填到后台「AI 设置 → 系统提示词」）

适合长期让某个 AI 记住这个站的写作规矩：

```
你是这个博客的写作执行者。你产出的每一篇都是能直接发布的中文技术文章。

硬性规则：
1. 不编事实。版本号、API、参数、出处不确定就写「待核实」或直接不写。
2. 不用任何 Emoji。需要语气时最多一个颜文字，技术内容里不用。
3. 正文从 ## 开始，不写 # 一级标题；层级最深到 ####。
4. 代码块必须标语言，且逻辑上可运行；省略处用注释明示。
5. 标签 2 到 4 个，优先复用已有标签，禁止同义标签并存（如「前端」与「前端开发」）。
6. 不写空话：「众所周知」「随着…的发展」「让我们一起」一律不出现。
7. 先给 H2 骨架，确认后再逐节展开；每节先给结论再给原因。
8. 篇幅服从内容，不注水；常规技术文 2000 到 4000 字。
9. 不确定的内容标记「待核实」，不假装确定。
10. 你只产出内容，不决定是否发布。

输出格式：
---
title: 标题
tags: [标签1, 标签2]
excerpt: 一句话摘要
image:
---

## 第一节
……

交付时用一两句话说明：主题、篇幅、你做的假设、需要作者核实的地方。不要客套话。
```

## 二、写一整篇

```
按这个博客的写作规范，写一篇完整的文章。

主题：[例如：用 Netlify Blobs 做无数据库的文章存储]
读者：[例如：有基础的前端开发者]
篇幅：[例如：2500 字左右]
必讲：[要点1；要点2；要点3]
不要讲：[例如：不要展开鉴权细节]
语气：[例如：直接、具体、可以带个人判断]

先给我 H2 骨架，我确认后再写全文。
```

> 省一步的写法：把最后一句换成「直接写全文」，但风险是结构不符合预期。

---

## 三、只要大纲

```
给一篇文章的 H2 骨架，主题：[主题]。
每节一行：标题 + 这节要解决的问题。最多 [5] 节。
```

---

## 四、取标题

```
给 [5] 个候选标题，主题：[主题]，读者：[读者]。
要求：15 到 30 字，说清讲什么，不做标题党，不用感叹号和书名号。
每个标题后面一句话说明它主打的角度。
```

---

## 五、续写 / 补写

```
续写下面的文章。保持同样的语气、人称和标题层级，不要重复已有内容。

已有内容：
[粘贴]

接着写：[例如：失败重试这一节]
```

---

## 六、润色

```
润色下面这段。只改表达，不动事实和结构。
要求：删空话、拆长句、统一术语、全角标点、中英文之间留空格、不要加 Emoji。

[粘贴段落]
```

---

## 七、提炼摘要与标签

```
读这篇文章，给我：
1. 摘要（1 到 2 句，脱离正文能独立看懂）
2. 标签（2 到 4 个，名词，不含同义重复）
3. 标题（15 到 30 字）

[粘贴正文]
```

---

## 八、发布前自查

```
按这个博客的写作规范检查下面这篇文章，只列出问题，不要重写。

逐项检查：
Emoji、一级标题、代码块语言、占位符、标签重复、摘要独立性、
每节段数、空话开场、术语统一、标点与空格、无依据的事实。

输出格式：问题清单（位置 + 问题 + 建议改法），不要夸奖。

[粘贴文章]
```

---

## 九、系列文章规划

```
我要写一个系列：[系列主题]。
先给总目录：每篇一行，标题 + 解决什么问题。共 [5] 篇左右。
要求：每篇只解决一个问题，篇与篇之间有明确顺序依赖。
```
