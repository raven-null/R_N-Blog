# 09 · 维护说明

> 这个文件夹是「博客使用指南」，人可以读，AI 也可以读。
> 本文件说明**怎么改它**——改哪、改完同步什么、怎么保证不跑偏。

---

## 一、定位

| 项 | 约定 |
|----|------|
| 服务对象 | ① 使用博客的人 ② 来博客写文章的 AI |
| 事实来源 | **代码**，不是旧文档。文档与代码冲突时以代码为准，然后回来改文档 |
| 写作风格 | 简洁、表格优先、每篇开头一句说明「这篇解决什么」 |
| 语言 | 简体中文；术语保留英文；正文不用 Emoji |

### 为什么人和 AI 共用一套文档

给 AI 的规范如果单独写一份，很快就会和给人看的版本漂移。
所以：**格式与规则只写一次**（[04-写作规范](./04-写作规范.md)），
[05-AI-写文章指南](./05-AI-写文章指南.md) 只写「AI 特有的约束和执行流程」，不重复格式细节。

---

## 二、事实从哪来

改任何一处说明前，先去对应位置核对：

| 想写的内容 | 去哪里看 |
|------------|----------|
| 文章字段、状态、分章阈值 | `netlify/functions/admin.ts`（`ArticleMeta`、`CHUNK_THRESHOLD`） |
| 存储分哪些 Blobs | 同上，以及 `_shared/blob.ts` 里的 store 名 |
| 后台密钥规则 | `netlify/functions/_shared/auth.ts` |
| 访客 AI 人设与禁 Emoji | `public/js/chat.js` 的 `systemPrompt` |
| 写作助手的能力边界 | `netlify/functions/admin.ts` 的 `WRITE_SYSTEM_PROMPT`、`public/js/write-ai.js` 头注释 |
| 前台 AI 代理与密钥不下发 | `netlify/functions/ai.ts` |
| 导入解析哪些字段 | `public/js/admin-app.js` 的 `importAndEdit` |
| Markdown 支持/已移除语法 | `public/js/markdown-config.js` |
| 阅读页快捷键 | `public/js/reader.js` |
| 当前版本号 | `public/js/admin-edit.js` / `admin-app.js` 里的注释头 |

## 三、改指南的流程

1. **定位**：要改的是「给人看的操作」还是「给 AI 的规则」？只改该改的那一篇。
2. **核对代码**：按上表确认现状，别照抄旧文档（`docs/操作文档.md` 是 v2.6 时代的历史文档，很多内容已失效）。
3. **改正文**：保持风格——短句、表格、开头一句话目标、结尾给下一步。
4. **同步**（见下节）。
5. **记一笔**：在本文末尾的版本记录里加一行。

## 五、文档本身的检查清单

- [ ] 相对链接都能打开（`./xx.md`）
- [ ] 没有残留「posts/」「manifest.json」等旧架构说法
- [ ] 命令、字段名、API 名与代码一致
- [ ] 表格没有超宽
- [ ] 同一概念在各篇里的叫法一致（如统一叫「写作助手」，不混「AI 写作」「写作 AI」）
- [ ] 原则性表述写成可判断的句子（「不用 Emoji」而不是「尽量少用表情」）
