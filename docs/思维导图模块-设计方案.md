# 思维导图模块 · 设计方案（讨论稿 v0.1，未动工）

> 目标：在博客内容体系中新增第三种可交互形态「思维导图」，与现有「白板（Excalidraw）」并列。
> 本文件只做设计，暂不写任何功能代码。文末列出需要你确认的决策点。

---

## 1. 定位与使用场景

- **内容形态**：`type: "mindmap"`，与 `article` / `whiteboard` / `card` 并列
- **展示形态**：整页导图（无目录侧栏），交互可缩放/折叠/导出
- **典型用途**：知识结构梳理、长文大纲、项目拆解、读书笔记
- **与白板的区别**：白板是自由画布（图形/连线/贴图），导图是**结构化树**（自动布局、增删即重排），两者互补，互不干扰

---

## 2. 技术选型

| 候选 | 优点 | 问题 | 结论 |
|---|---|---|---|
| **Mind Elixir** | 原生 JS 无框架依赖、中文文档、支持 Markdown 纯文本、社区活跃（有 Obsidian 插件与桌面版）、API 简洁 | 需核实协议与包体积；导出能力可能需插件 | **推荐作为编辑内核** |
| jsMind | 老牌、体积小 | 样式与交互偏旧，移动端体验一般 | 备选 |
| markmap | Markdown 直接渲染、只读展示好 | 编辑能力弱 | 可选：作为「Markdown 只读预览」补充（P2） |
| AntV G6 / react-flow / GoFlow | 图能力全面 | 偏通用图/流程，体积大或需框架 | 不采用 |
| GoJS | 功能最强 | 商业授权 | 不采用 |
| 自研 SVG | 完全可控 | 拖拽/自动布局/折叠/导出全部自建，成本高 | 不采用 |

**选型核实结果（已核实）**：
1. 许可协议：**MIT**（`npm view mind-elixir license` 实测返回 MIT，可商用、可再分发）
2. 版本：稳定版 **5.15.1**——注意 npm 上的 `latest` 标签指向 `6.0.0-next.4`（预发布），实施时必须显式安装 `mind-elixir@5.15.1`，不要直接 `npm i mind-elixir`
3. 体积：5.14.0 的 unpackedSize ≈ **488KB**（含 dist/ 与类型文件），实际打包 gzip 体积待实施时实测（目标 < 200KB）
4. 导出能力（PNG / SVG）与数据结构稳定性：实施第一步在最小样例里实测确认

**环境约束（实测）**：本机沙箱下 npm 默认缓存目录 `%LOCALAPPDATA%\npm-cache` 不可写（EPERM），须把缓存指到工作区内可写目录，例如：
`npm view mind-elixir version --cache .local-data/npm-cache`、安装同理加 `--cache`。网络本身可通。

## 3. 架构（刻意与白板模块保持一致）

```
public/mindmap.html              独立编辑器页（供 iframe 内嵌，与 excalidraw.html 同级）
public/js/vendor/mindmap/
    mindmap-editor.v1.js         构建产物（版本化命名，immutable 缓存）
    mindmap-editor.v1.css
scripts/mindmap/editor.ts        编辑器封装：加载/保存/口令/主题/Markdown 互转/导出
scripts/build-mindmap.mjs        构建脚本（esbuild → IIFE，模式对齐 build-excalidraw.mjs）
netlify/functions/mindmap.ts     后端 API（Blobs store：mindmaps）
```

**沿用已验证的做法**：
- 独立页 + iframe 隔离（避免样式与全局变量互相污染，白板已验证有效）
- 复用 `_shared/blob.ts`、`_shared/auth.ts`、统一的响应封装与 `Cache-Control` 约定
- 版本常量统一（`MM_BUNDLE_VERSION`），并在构建脚本里**自动改写所有引用点**——吸取上次白板升版漏改 `article-app.js` 导致 404 的教训

## 4. 数据模型

Blobs store：`mindmaps`

| key | 内容 |
|---|---|
| `notes/<id>/meta` | `{ id, title, createdAt, updatedAt, rev, editable, editKeyHash }`（与白板同构） |
| `notes/<id>/scene` | 导图数据 JSON |
| `notes/<id>/rev/<n>` | 历史快照（保存时把旧版入快照，用于回滚） |

导图数据（直接持久化库的 `nodeData` 结构，外加版本与外观字段）：

```json
{
  "v": 1,
  "nodeData": { "id": "root", "topic": "中心主题", "children": [ { "id": "n1", "topic": "分支", "children": [] } ] },
  "theme": "default",
  "layout": "mindmap",
  "direction": 1
}
```

文章记录（`blog-articles`）中：`{ type: "mindmap", mapId: "<noteId>", content: "" }`，与白板文章的 `boardId` 完全同构。

**体积评估**：导图是纯文本树，通常几 KB 到几十 KB，**不存在白板那种「内嵌图片撑爆 6MB 请求体」的问题**；若将来支持嵌入图片，直接复用白板已实现的「逐张单独存储 + 压缩」方案。

## 5. 后端 API（`/api/mindmap`，仿 `excalidraw.ts`）

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| GET | `?id=<id>` | 读导图 + 公开 meta（rev / editable / hasKey / title） | 公开 |
| PUT | `?id=<id>` | 保存（`baseRev` 乐观锁；旧版入快照） | 管理员，或 `editable=1` 且口令匹配 |
| POST | `?action=meta&id=` | 改标题 / 权限 / 口令 | 管理员 |
| GET | `?action=history&id=` | 快照列表（revs + current） | 管理员 |
| POST | `?action=rollback&id=&rev=` | 回滚到指定快照 | 管理员 |
| POST | `?action=delete&id=` | 删除导图（含全部快照） | 管理员 |

- 幂等、错误信息与白板保持一致（前端可复用同一套提示）
- 可选：`GET ?action=export&id=&format=md|json` 服务端导出（默认不做，见决策点 B）

## 6. 前端接入点（博客）

1. **阅读页** `article.html`
   - 新增形态分支：`type=mindmap` → 整页导图（只读 + 缩放/折叠/导出）
   - 复用白板的全屏模式容器（现有 `body.board-mode` 那套），按类型懒加载对应 bundle；导图 bundle 只在遇到导图文章时加载
2. **编辑页** `admin-edit.html`
   - `mindmap` 类型 → iframe 内嵌 `/mindmap.html?note=<id>&edit=1`（与白板 `.ee-frame` 同构）
   - 侧栏现有的「白板管理」卡片**泛化为「画板 / 导图管理」**：接口按类型切换，其余逻辑（改名/权限/口令/回滚/删除）完全复用
3. **后台** `admin.html`
   - 写文章形态切换增加「思维导图」（当前是 文章 / 随记 / 白板）
   - 发布弹窗沿用现有字段（标题 / 状态 / 标签 / 封面），提交 `type: "mindmap"` + `mapId`
   - 工具栏按钮与白板形态一致：新建导图 / 设为只读 / 设口令 / 发布
4. **首页**
   - 卡片右下角形态文字：新增「思维导图」（现有是「交互白板」/「博客文章」）
   - 导航筛选：`全部 / 文章 / 白板 / 随记` → 增加「导图」
5. **随记（card）**：不涉及

## 7. 权限与安全

- 完全沿用白板模型：默认公开只读；笔记可设 `editable=1`（公开可编辑）或 `editKey` 口令
- 管理操作（改名/权限/口令/回滚/删除）全部要求管理员密钥
- 导图内容一般用于公开文章，无 R18 之类的分级需求（如将来需要，可直接复用图库项目刚实现的 R18 分级思路）

---

## 8. 交互设计（编辑页）

- 顶栏（吸取白板教训，**不做满宽工具栏**）：
  - 左上：返回 / 标题
  - 右上：保存（Ctrl+S）、导出（PNG / SVG / Markdown）、更多
  - 与博客一致的深色液态玻璃风格
- 键盘：Tab 子节点、Enter 同级、Delete 删除、方向键导航、Ctrl+Z 撤销（库内置，需核对）
- 移动端：以查看为主（缩放/折叠/导出）；编辑建议桌面端
- 原生化体验：保存反馈提示（rev 号 + 时间），与白板一致

---

## 9. 导出与互操作（重点卖点）

- **PNG / SVG 导出**：直接给文章配图或分享（能力取决于库，动工前核实）
- **Markdown 大纲双向转换**：

```markdown
# 中心主题
## 分支一
### 子节点
- 叶子节点
```

  - Markdown → 导图：粘贴大纲一键生成（写文章时先列大纲再转导图，非常实用）
  - 导图 → Markdown：导图转成大纲贴进文章正文
  - 转换器自研（约 80~120 行，双向），不额外引入依赖
- 可选 P2：文章正文里嵌入只读导图（类似现在的白板嵌入）

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| 库的协议或体积不达标 | 动工第一步先核实；备选 jsMind；最差自研精简 SVG 版本 |
| 新增第 5 个 bundle 后再出现版本漏改 | 构建脚本自动改写全部引用点（脚本化，不靠记忆） |
| 阅读页全屏模式与白板冲突 | 复用同一容器，按类型懒加载各自 bundle，互不加载 |
| 移动端编辑体验差 | 移动端只做查看 + 导出；编辑引导到桌面端 |
| 与白板功能边界模糊 | 明确：结构化树用导图，自由绘制/贴图用白板；首页卡片与导航分别可筛 |
