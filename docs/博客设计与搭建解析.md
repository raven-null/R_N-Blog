# 博客设计与搭建解析（代码级）

> 这篇从代码层面拆解本博客的架构：纯前端静态站 + Netlify Functions + Netlify Blobs，不依赖传统后端框架，零服务器成本、可本地运行、可一键部署。

---

## 一、架构总览

```
┌─────────────────────────────┐
│  浏览器（纯静态前端）          │
│  index.html / article.html  │
│  admin.html / js/ / css/    │
└──────────────┬──────────────┘
               │ HTTP（fetch / SSE）
┌──────────────▼──────────────┐
│  Netlify Functions（Node）   │  netlify/functions/
│  admin / ai / agent / ...   │
└──────────────┬──────────────┘
               │ @netlify/blobs
┌──────────────▼──────────────┐
│  Netlify Blobs（键值存储）    │
│  blog-articles / blog-images │
│  newsnow-comments / ...      │
└─────────────────────────────┘
```

- **前端**：`public/` 下纯静态 HTML/CSS/JS，无构建步骤，`netlify.toml` 直接发布该目录
- **后端**：Netlify Functions v2（`export default` 风格，路径由 `config.path` 或 `netlify.toml` 重定向注册）
- **存储**：全部数据落在 Netlify Blobs（键值存储），按用途分多个 store
- **AI**：OpenAI 兼容接口直连大模型（智谱/DeepSeek/Kimi…），Key 存于后台设置，聊天在浏览器直连、写作与 Agent 走后端

## 三、后端：统一响应与跨域

所有函数返回标准 `{ status, message, data }`，跨域统一处理：

`netlify/functions/_shared/cors.ts`：

```ts
export function json(status: number, body: any, req?: Request): Response {
  return new Response(JSON.stringify(body), {
    status,
    headers: { ...corsHeaders(req), "Content-Type": "application/json; charset=utf-8" },
  })
}
```

`allowedOrigins()` 读取 `ALLOWED_ORIGIN` 环境变量（默认 `https://ravennull.work`），开发环境自动放行 localhost。

## 四、认证体系

`netlify/functions/_shared/auth.ts`（收敛三处重复后唯一）：

```ts
export async function getAdminPassword(): Promise<string> {
  const envPwd = process.env.ADMIN_KEY
  if (envPwd) return envPwd
  // 否则读 Blobs blog-auth，默认 "1111"
}
export async function checkAuth(req: Request): Promise<boolean> {
  return (req.headers.get("x-admin-key") ?? "") === (await getAdminPassword())
}
```

后台所有写操作（发文章、删评论、改设置、AI Agent 管理等）都过 `checkAuth`；前台只读接口公开。

## 五、数据存储：Netlify Blobs

`netlify/functions/_shared/blob.ts` 封装了 `getBlobStore(name)`，本地开发自动回退到 `.local-data/` 文件，方便调试：

| Store | 用途 | 关键 key |
|-------|------|----------|
| `blog-articles` | 文章 | `index`（元数据索引）+ 每篇文章 `{id}` |
| `blog-images` | 图库图片 | 每张图 `{key}` |
| `newsnow-comments` | 留言 | `post:{postId}` |
| `blog-settings` | 博客设置 / 卡片排序 | `site` / `setting-order` |
| `blog-auth` | 后台密码 | `password` |
| `blog-tag-registry` | 标签注册表 | `index` |
| `blog-agent-tasks` | AI Agent 任务 | `task:{id}` + `index` |
| `blog-chat` | AI 会话 | `client:{clientId}` |

### 文章索引（关键设计）

文章用「索引 + 正文」双份存储：`admin.ts` 维护一个 `index` 数组（元数据：id/title/tags/excerpt/image/status/date…），首页只读索引即可渲染卡片；打开单篇再读正文。发布/编辑时用**强一致读取**再 `unshift` 置顶。

```ts
// _shared/articles.ts 里的创建逻辑（admin 与 Agent 共用）
const index = await getArticleIndexStrong()   // 强一致，避免读到旧数据
const meta = { id, title, tags, date: now, status, ... }
index.unshift(meta)
await saveArticleIndex(index)                 // 置顶
```

## 六、前台：文章与 Markdown

- 首页 `index.html` 请求 `/api/admin?action=articles` 拿索引渲染瀑布流，元数据缓存于 sessionStorage
- 文章页 `article.html` 按 `id` 拉取正文，交给 `js/markdown.js` 的 `MarkdownParser`（基于 marked）渲染，并注入代码块组件（语言角标 + 复制按钮）、图片灯箱、目录生成

## 七、留言系统

`comments.ts`：

- `POST /api/comments { postId, name, content, image }` → 清洗（去 HTML、折叠空白、限 5000 字、最多 3 条链接）→ 追加到 `post:{postId}`
- `GET ?postId=` 读列表；`DELETE` 需后台密钥
- 留言区前端渲染：`@昵称` 高亮、`/article.html?id=` 转可点击链接、图片灯箱

## 八、AI 体系（重点）

### 8.1 内置模型库（免填接口地址）

`netlify/functions/_shared/models.ts`：

```ts
export const MODEL_CATALOG: CatalogProvider[] = [
  { id: "zhipu", name: "智谱 GLM", models: [
    { id: "glm-4-flash", label: "GLM-4-Flash", apiUrl: ".../chat/completions", tags: ["免费","快速"] },
    ...
  ]},
  // deepseek / openai / moonshot（Kimi）/ qwen / 自定义
]
export function resolveModelApiUrl(provider, model, fallbackUrl) {
  const found = findCatalogModel(provider, model)
  return (found && found.apiUrl) || fallbackUrl   // 自定义/旧配置回退手填地址
}
export function resolveTemperature(provider, model, fallback) {
  // Kimi K2 等模型只接受 temperature=1，这里钳制
  return found?.temperature ?? fallback
}
```

后台设置只存 `{ provider, model, apiKey }`，请求时后端自动解析出真实接口地址；旧配置无 provider 时按自定义兼容。

### 8.2 聊天（前台直连）

`js/chat.js` 直接从浏览器请求大模型（Key 来自后台设置，按模型钳制 temperature），实现流式、多会话、划词、`/` 指令。文章页注入当前文章内容为上下文，直接提问即可回答文章相关问题。

会话持久化走 `/api/chat`：按访客 `clientId` 存到 Blobs，防抖同步。

### 8.3 写作 AI（后端流式代理）

`ai.ts`（`/api/ai`）：后台「AI 写作」侧栏调用，**鉴权 + 组装 Prompt + SSE 透传**，Key 不暴露给页面。写作人设用「写作 AI 提示词」或默认，不借用聊天人设。

### 8.4 AI Agent（异步任务 + 后台函数）

这是最复杂的一环，拆成三块：

**① 任务接口 `agent.ts`（同步）**
- 创建任务（写 Blobs `task:{id}`），生成 `pollKey` 供前端公开轮询进度
- 按来源区分：`admin`（后台面板，需 X-Admin-Key）/ `chat`（对话里 @管理员，需后台密钥 body.adminKey）
- 立刻通过 `kickAgentRun` 请求后台函数 `/api/agent-run`，**最多等 3 秒**（后台函数应秒回 202）

```ts
async function kickAgentRun(taskId, runKey, baseUrl) {
  const target = new URL("/api/agent-run?task=" + taskId, baseUrl.origin).href
  const controller = new AbortController()
  const timer = setTimeout(() => controller.abort(), 3000)   // 不阻塞主响应
  await fetch(target, { method: "POST", headers: { "x-agent-run-key": runKey }, signal: controller.signal }).catch(() => {})
}
```

**② 后台执行器 `agent-run.ts`（Background Function）**

`netlify.toml` / `config.background: true` 声明为**后台函数**（最长运行 15 分钟，客户端立即收到 202）：

```ts
export const config = { path: "/api/agent-run", background: true }
```

`runTask` 内部：
- 幂等保护（done 不重复跑；running 且未超 15 分钟不重跑）
- 分「文章 / 问答」两类任务
- 文章任务：`generateFullArticle` **分段续写**（每次 `chatComplete`，`finish_reason === "length"` 则再发「继续写」，最多 12 段）→ 二次调用提取标题/标签/摘要 → `createArticle` 发布 → 从图库随机挑封面
- 每阶段更新 `task.progressPercent`，前端据此画进度条

**③ 前端（聊天窗口）**

`chat.js` 拦截 `@管理员` 指令 → `prompt()` 要后台密钥 → `POST /api/agent`（source=chat）→ 拿 `pollKey` 每 3 秒轮询 `GET /api/agent?task=&key=`（凭 pollKey 可公开查）→ 用 `updateAgentProgress` 画进度条 → 完成后展示文章链接。

### 8.5 三套提示词分离

- **AI 助手**（聊天）：`ai.systemPrompt`
- **写作 AI**：`writingAi.systemPrompt`（写作/Agent 用，留空回退默认写作人设）
- **AI Agent**：`agent.systemPrompt` + `shareWritingPrompt` 开关（默认与写作共用）

## 九、图片系统

- 后台上传走 `admin.ts` 的 `action=images`，`sharp` 压缩转 WebP（1920px 内、质量 82），存 Blobs `blog-images`
- 前台图库/文章图片通过 `image.ts` / `admin-image.ts` 按 key 输出；文中图片独立存 `article-image.ts`（`blog-articles` 外的独立 store），删除不影响图库
- 封面：文章保存时若未设封面，自动从图库随机挑一张

## 十、部署与路由

`netlify.toml`：

```toml
[build]
  publish = "public"
[functions]
  directory = "netlify/functions"
  node_bundler = "esbuild"        # Functions 用 esbuild 打包
[[redirects]]
  from = "/api/admin"             # 重定向到函数
  to = "/.netlify/functions/admin"
  status = 200
```

`/api/agent-run` 是后台函数（`background: true`），普通请求重定向到它时 Netlify 立即回 202，函数在后台继续跑。

## 十一、安全要点

- 后台写接口一律 `checkAuth`（X-Admin-Key）
- 评论区注入防护：HTML 剥离、长度/链接数限制；渲染前转义
- AI Agent 生成文章需后台密钥（对话里 @管理员 输入），防止公共接口被刷成本
- `agent-run` 后台函数调用用独立令牌 `x-agent-run-key`（`sha256(密码+":agent-run")`）校验
- 模型 Key 存于 Blobs 设置，页面不落明文；写作/Agent 走服务端，不暴露给浏览器

## 十二、扩展方向
