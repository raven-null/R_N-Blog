# 桌宠（渡鸦）现状说明

右下角那只黑色弹簧小生物。本文记录它的组成、交互、可调参数和测试方式，
改之前先看一遍，免得又出现"两份实现各修一半"的老问题。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `public/js/pet-core.js` | 内核：引擎创建、拖拽、单击/双击、睡眠、位置记忆、气泡与面板定位、空闲小动作、页面可见性暂停 |
| `public/js/pet-mind.js` | 心智：页面感知、本地台词库、主动搭话、`/api/ai` 流式对话、语音输入、朗读、安静模式、对话历史（仅内存，刷新即清） |
| `public/vendor/grok/*` | 第三方动效引擎（弹簧动画 / 多边形眼睛 / 状态机），`character.js` 有本地补丁，见 `vendor/grok/README.md` |
| `public/js/pet-boot.js` | 兼容壳：老页面若还引用它，只会转调 `PetCore.init()` |
| `public/js/app.js` | 首页里 `initDeskPet()` 与 `petSay/petPlay/...` 都只是转发到 `PetCore` 的薄包装 |
| `public/css/style.css` | `.deskpet*` / `.pet-chat*` / `.pet-chips` 段落（改完要 `pnpm run build:css`） |
| `public/index.html`、`public/article.html` | 桌宠 DOM + 空闲注入脚本（DSH-LAZY） |

两份 HTML 的桌宠结构必须保持一致：`#deskPet` > 气泡 + `#deskPetBody`（底座 / SVG / zZz）+ `#petChat`（极简输入条：只有输入框 / 麦克风 / 发送，回复走气泡）
（标题、🔈 朗读、🔔 安静、`×`、消息区、快捷问题、输入框）。

## 交互

| 操作 | 结果 |
| --- | --- |
| 左键单击桌宠 | 只是摸一下：跳一下 + 冒一句本地台词（**不开对话框**）；正在朗读时点一下就是打断 |
| 双击桌宠 | 召唤 / 收起旁边的两个圆（打开对话框 / 睡觉） |
| 按住桌宠不放（约 0.6 秒后生效） | 像语音输入：按住期间直接说，松手把这句话**当任务发出去**；等它把回复说完、朗读念完才收工；按住会先停掉正在念的回复（抢话） |
| 点圆里的 💬 | **对话框只从这里打开** |
| 点圆之外的地方 / Esc | 收起这两个圆 |
| 拖动 | 带惯性 + 贴边；位置按视口比例记住，窗口变化后夹回可见区（开始拖动时会收起这两个圆） |
| 右键 / 中键 | 一律忽略（连待执行的单击也会被取消） |
| 待机 | 22–48 秒随机换个小动作；眼睛一直跟着鼠标（身体会轻微探身） |
| 页面切后台 | 引擎暂停绘制，回来继续 |

两个圆（双击召唤）：💬 打开对话框 / 🌙 睡觉·唤醒。实时对话不占圆位，靠按住桌宠。
单击和双击都不再控制对话框；睡觉也不再靠双击，走月亮那个圆。

判定方式：单击立即响应（只冒一句）；双击在 380ms 内立刻切换两个圆；按住 620ms 进入按住说话，
松手发送并结束，这次按下也不再当成点击。开始拖动会取消按住判定。

「实时对话」和「打开对话框」是两条路：对话框是打字聊，实时对话只用桌宠气泡，
连说连听（`continuous` 识别 + 自动发送 + 朗读回复），退出口径是再长按一次 / 麦克风被拒。

按住说话（长按桌宠）：气泡里会把你说的拼起来（已定稿 + 还在说的都算），
**按住期间只攒不发送** —— 换气停顿、识别中途给出 final 都不会提前回答；
松手才整句发出去。识别自己结束但手还按着时，会自动接着听。

输入条（桌面端）跟着桌宠走：优先在桌宠上方，放不下翻到下方，四边夹在视口内；
窄屏（≤900px）交给 CSS 贴边。屏保模式（`body.screensaver-on`）下桌宠整体隐藏。

对话历史只存在内存里：**刷新或换页就自动清空**（启动时还会顺手删掉旧版本留在
localStorage 里的 `pet-history`），不做任何持久化。

## 可调参数（`pet-core.js` 的 `ensureEngine`）

| 参数 | 当前值 | 作用 |
| --- | --- | --- |
| `gazeRange` | `{x:52, y:34}` | 眼球位移幅度（原引擎写死 22/14，58px 下几乎看不见） |
| `gazeClamp` | `0.85` | 归一化上限 |
| `gazeFalloff` | `12` | 多远算"看得很偏"，约 700px 才满幅；原值 2（120px）会导致鼠标一离开就顶满 |
| `followPointer` | `true` | 眼睛跟随常开（不受 reduced-motion 影响） |

主动说话节奏在 `pet-mind.js` 的 `STATE`：白天 `autoMs [70s, 155s]`、夜间 `nightAutoMs [150s, 300s]`，
两次之间至少 `minGap 50s`；用户刚聊过 20 秒内不插话；切换视图的招呼有 15 秒冷却。

## 后台设置（设置 → AI 设置 → 桌宠）

| 字段 | 作用 |
| --- | --- |
| 显示桌宠 | 关掉后前台整个不渲染（访客也看不到） |
| 主动搭话 | 关掉后只有被点击时才说话 |
| 眼睛跟着鼠标 | 关掉引擎 `followPointer`，身体也不再探身 |
| 说话频率 | 安静 / 正常 / 话多 → `autoMs` 约 120–260s / 38–88s / 20–45s（默认比早期更快） |
| 名字 | 开场白、AI 人设里的称呼（输入条里不显示标题） |
| 性格 / 口吻 | 追加到 `/api/ai` 的 system prompt |
| 默认朗读回复 | 前台已没有朗读开关，这个值就是唯一来源（访客手动切换过的记录仍优先） |
| 语速 / 音调 | 0.6–1.6，传给 `SpeechSynthesisUtterance.rate / pitch` |
| 音色 | 下拉选晓晓 / 晓伊 / 瑶瑶 / 慧慧 / 云希 / 云健 / 康康 / Google 普通话，或选「自定义关键词」手填；换一个会自动试听一句，也可以点「▶ 试听这个音色」；本机没有对应声音就退回自动 |

音色是**本机资源**：后台填的关键词会在访客本机的语音列表里做模糊匹配，匹配不到就退回自动。
前台输入条不再提供音色下拉（访客可用 localStorage 的 `pet-tts-voice` 覆盖）。

对话本身用的是「AI 助手」那套厂商 / 模型 / 密钥（`/api/ai`），桌宠没有独立密钥；
AI 助手关掉时桌宠也不会回话。

存储与通道：Netlify Blobs `blog-settings/site` 的 `pet` 字段。
`GET /api/admin?action=settings` 是公开的（首页本来就在读，`pet` 里没有密钥），
保存走 `POST /api/admin?action=settings`（需 `X-Admin-Key`）。
请求不带 `pet` 时会沿用库里的值，避免旧缓存的后台页面把作者配好的桌宠设置重置。

## 跟着音乐说话

音乐页的 Folia 播放器（跨域 iframe）会用 `postMessage` 广播
`{ type: 'folia:now-playing', song, lyric, playing }`，桌宠直接复用这条通道，
所以它知道此刻在放什么：

- 换歌后约 2.6 秒开口一句（插值歌名 / 歌手，有一半概率用当前歌词）
- 播放中每约 2.5 分钟再冒一句
- 每首歌最多让 AI 感慨一次（带歌名 / 歌手 / 当前歌词，播放满 30 秒后触发），失败就算了
- 朗读时会把音乐**先暂停**，说完（或被打断）再继续——跨域 iframe 改不了音量，只能走
  Folia 的 olia:control / toggle；只在确实在播、且是我们暂停的那次才恢复
- 只在安静模式关闭、没睡着、页面可见时发生；「正在听什么」也会写进 AI 现场上下文，
  所以你问「这首怎么样」它能接得上

## 图标风格

输入条里的麦克风 / 发送，以及双击浮出的两个圆，统一用细线条 SVG：
`stroke: currentColor; stroke-width: 1.6`、`viewBox="0 0 24 24"`，跟主题色走，不用 emoji。
开关类按钮里放两个 svg（`.pet-ico-on` / `.pet-ico-off`），靠 `.is-on` 类切换。

## 测试

```bash
node scripts/test-ui.mjs        # 含桌宠内核断言：单击 / 双击睡觉 / 拖拽记忆 / 气泡不越界
pnpm run build:css              # 改过 style.css 必须重新打包
pnpm run lint:css               # 只有 warning（全站历史 !important）
```

需要真实浏览器验证时的做法：起 `node .local-data/preview.mjs`（静态预览，`/api/ai` 返回 501），
再用无头 Chrome + CDP 读 `window.PetCore.engine.pointer`、`gazeRange`、元素 `getBoundingClientRect()`
来量化"眼睛有没有跟着转、气泡/面板有没有越界"，比截图肉眼看可靠。

## 已知限制

- AI 对话依赖 `netlify dev`（`netlify/functions/ai.ts`）与 `ZHIPU_API_KEY` / 后台设置里的 key；纯静态预览会提示"AI 还没接上（HTTP 501）"。
- 语音识别走 Web Speech API，只有 Chrome / Edge 支持；Safari 会提示不可用。
- `prefers-reduced-motion` 只关掉 CSS 漂浮/跳跃与空闲小动作，引擎自身的呼吸/眨眼仍在。
