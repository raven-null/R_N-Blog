# 节点图模块 · 设计方案（v0.1，待确认）

> 目标：在博客内容体系中新增第四种可交互形态「节点图」——自由摆放节点、拖拽 socket 连线，与现有「思维导图（Mind Elixir）」**并列**。
> 本文件只做设计，暂不动功能代码。文末列出需确认的决策点。

---

## 1. 定位与边界

- **内容形态**：`type: "graph"`
- **展示形态**：整页节点图，交互可缩放/平移/连线/导出
- **与导图的关系**：**并列**。首页导航新增「节点图」筛选项，两者各自独立成文
- **与白板的关系**：**不做功能划界**。白板、节点图都允许自由摆放与连线，由用户自行选择用哪个，产品上不强制区分
- **代码关系（硬约束）**：三者代码严格隔离，互不 import、互不借用接口，只在「接入点」通过类型表注册
- **不做文本化输出**：**不提供「节点图 → Markdown / 大纲 / 文章正文」的转换，也不支持嵌入文章正文**。节点图只在画布里看，导出仅保留 PNG（内嵌存档）与 JSON。导图那套「大纲 ⇄ Markdown 双向转换」不复制过来

---

## 2. 选型：Weave（已核实）

| 项 | 结论 |
|---|---|
| 仓库 | `github.com/Quan-Chan/Weave` |
| 许可 | **Apache-2.0** —— 可商用、可修改、可再分发，需保留 LICENSE 与版权声明，修改处需注明 |
| 形态 | 单 HTML 文件，零框架、零依赖、零构建 |
| 规模 | `Weave.html` 580KB（gzip 187KB）／`Weave.min.html` 309KB（**gzip 80.6KB**） |
| 技术栈 | 原生 JS + HTML5 + CSS3 + Canvas 2D（网格）+ SVG（连线/分区）+ localStorage |
| 渲染 | **节点是 DOM 元素**（`#canvasNodes` 内 `<div class="node">`），缩放用 CSS transform |
| 自带能力 | 撤销/重做 50 步、PNG 导出（内嵌存档 JSON 可拖回还原）、框选/多选、分区、收起节点串、关联高亮、触控手势、只读模式、中英双语、键位自定义 |

**结论：采用。** 体积与现有导图 bundle（gzip 50.7KB）同一量级；节点为 DOM 渲染，多类型节点改造成本低。

**为什么只能 iframe 集成**：Weave 是一个**应用**不是库——自带全局 `App` 对象、自带顶栏/侧边栏/设置弹窗、启动即自初始化（M13 末尾 IIFE）。无法作为模块 import 进现有 bundle。集成方式与现在导图一致：`public/graph.html` 被 iframe 嵌入，与外层 `postMessage` 通信。

## 3. Weave 定制策略：零 diff 注入

**原则：上游 `Weave.html` 一行不改。** 所有定制由构建脚本在注入点追加，上游升级时重跑脚本即可。

**注入点**：`/* ══ M13 · 装配与启动` 之前（第 10662 行附近）。此时 M01–M12 的 `App` 方法已全部定义完毕，启动 IIFE 尚未执行。

**注入内容（四块）**：

| 块 | 做法 | 覆盖的原方法 |
|---|---|---|
| 存储适配 | `Object.assign(App, {...})` 用 API 版替换 localStorage 三件套 | `_lsGet` / `_lsSet` / `_lsGetJson` |
| 多类型节点 | 包装原方法：先调原渲染，再按 `kind` 覆写 `.node-body` | `_updateNodeAppearance` |
| 样式 | 注入 `<style>` | —— |
| 外壳 | 保存胶囊、口令浮条、只读态、与父页 postMessage | —— |

**收益**：上游 `Weave.html` 与我们的定制产物之间 diff 为零，升级 = 重新注入 + 跑冒烟。代价是**依赖注入点稳定**——若上游重命名这些方法，需同步调整（见 §9 风险）。

## 4. 数据模型

沿用 Weave 存档格式，外层包一层信封：

```json
{
  "v": 1,
  "format": "weave-graph",
  "mode": "graph",
  "data": {
    "nodes": [ { "id": "n1", "label": "中心", "desc": "", "color": "blue",
                 "x": 0, "y": 0, "w": 9, "h": 4, "kind": "text" } ],
    "connections": [ { "id": "c1", "from": "n1", "to": "n2", "label": "" } ],
    "regions": [],
    "viewport": { "panX": 0, "panY": 0, "scale": 1 }
  }
}
```

- 节点 `x/y/w/h` 沿用 Weave 的**格单位**（1 格 = `GRID_PX` 像素），不做折算，避免与上游格式漂移
- 新增 `kind` 字段，缺省 = `text`，**老存档天然兼容**
- 文章记录中 `{ type: "graph", graphId: "<id>" }`，与 `mapId` / `boardId` 同构

**节点类型与字段**：

| kind | 内容 | 渲染 |
|---|---|---|
| `text`（缺省） | `label` + `desc` | Weave 原生，不改 |
| `image` | `data: { fid, w, h }` | 图片铺满 body，`object-fit: cover` |
| `code` | `data: { lang, code }` | `<pre><code>` + 高亮 + 复制按钮 |
| `article` | `data: { articleId, title, cover, excerpt }` | 封面 + 标题 + 摘要卡片，点击跳转文章 |

> `article` 节点是本博客独有的价值点：让节点图成为**文章之间的引用网络**。

## 5. 存储与后端

**新 store、新接口，不复用白板通道**（注意：现有导图的图片上传借用了 `/api/excalidraw?action=file`，节点图不沿用这种做法）。

| 项 | 值 |
|---|---|
| Blobs store | `graphs` |
| 路由 | `/api/graph` |
| key 结构 | `notes/<id>/meta`、`notes/<id>/data`、`notes/<id>/rev/<n>`、`notes/<id>/files/<fid>` |
| 接口 | GET 读 / PUT 保存（`baseRev` 乐观锁 + 旧版入快照）/ `action=meta` / `action=history` / `action=rollback` / `action=delete` / `action=list` / `action=file`（图片上传下载） |

结构照抄 `netlify/functions/mindmap.ts`（322 行，已验证），仅换 store 名与路由，**快照上限同样 50 份**。

**存储适配的关键难点**：`localStorage` 是同步的，`fetch` 是异步的。Weave 的启动流程同步读取存档后立即渲染，需要：

1. 注入层先 `fetch` 拉存档 → 写入一个内存 shim → 让上游的同步 `_lsGet` 读到
2. `_lsSet` 改为异步队列（防抖 500ms 与上游 `debouncedAutoSave` 对齐），失败提示并保留重试
3. 保存出口对接 `baseRev` 乐观锁；409 时提示而非静默覆盖

## 6. 接入点改造：先抽类型表

**问题**：现有代码里「画布类形态」的判断是硬编码的 `type === 'whiteboard' || type === 'mindmap'`，共 6 处分散在 5 个文件。直接加第三个模块，等于把这 6 处再拉长一截。

**做法**：先抽一张类型表（新文件 `public/js/content-types.js`，挂 `window.CONTENT_TYPES`，供各页面直接引用），把散落判断改成查表。

```js
window.CONTENT_TYPES = {
  article:   { label: '文章', short: '文', page: null,            api: null,          store: null,            hue: [220, 20, 30] },
  card:      { label: '随记', short: '记', page: null,            api: null,          store: null,            hue: [40, 20, 40] },
  whiteboard:{ label: '白板', short: '白', page: '/excalidraw.html', api: '/api/excalidraw', store: 'excalidraw', hue: [30, 40, 45] },
  mindmap:   { label: '导图', short: '图', page: '/mindmap.html',    api: '/api/mindmap',    store: 'mindmaps',   hue: [168, 30, 25] },
  graph:     { label: '节点图', short: '网', page: '/graph.html',     api: '/api/graph',      store: 'graphs',     hue: [265, 35, 30] }
```

## 7. 分阶段实施

**P0 · 跑通只读（先验证集成方式）**
1. 上游 min.html → 注入最小补丁 → `public/graph.html`，本地能打开、能画、能存 localStorage
2. `/api/graph` 全套（读写/乐观锁/快照/回滚/删除/列表/文件）
3. 存储适配层换成 API，验证刷新后数据回来
4. 文章页整页只读展示（iframe）

**P1 · 编辑闭环**
5. 编辑页内嵌（`admin-edit` + `editor-embed-admin` 对齐导图）
6. 后台写文章页「节点图」形态、保存胶囊、口令、只读态

**P2 · 多类型节点**
7. `kind` 渲染分支（image / code / article）
8. 右键「转换为图片/代码/文章节点」+ 各自的编辑弹窗
9. 图片上传走 `/api/graph?action=file`，保存时转 WebP

**P3 · 收尾**
10. 首页导航「节点图」+ 卡片形态文字 + 缩略图
11. 类型表重构（§6）——可与 P1 并行

> 明确不做：与导图的互转、Markdown / 大纲导出、正文内嵌只读节点图。导出的终点就是 PNG 与 JSON。

## 8. 与现有导图的差异（用户可感知）

| | 导图（Mind Elixir） | 节点图（Weave） |
|---|---|---|
| 结构 | 树，自动布局 | 自由摆放，任意连线 |
| 排版 | 系统排 | 自己排 |
| 撤销 | 无 | 50 步 |
| 导出 | PNG / SVG / JSON | PNG（内嵌存档，可拖回）/ JSON |
| 文本转换 | 规划中（大纲 ⇄ Markdown） | **不做**，只在画布里看 |
| 特色 | 行式大纲、折叠、待办、备注 | 分区、收起节点串、关联高亮、时序图 |

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| **上游改方法名 → 注入点漂移** | 注入脚本先做「注入点存在性检查」，缺失即构建失败并报错，不静默产出坏页面；冒烟测试覆盖四个覆盖点 |
| **localStorage 同步 → fetch 异步** | 用内存 shim 挡在中间，上游同步读的语义不变；保存走队列，失败可见 |
| **上游无版本号锚点** | 克隆时记录 commit hash 到注入产物的注释头；升级时按 hash 比对 doc |
| **上游测试台架（19 个文件 + golden.json）不迁移** | 不追求与上游测试对齐，只自建 3 个冒烟：能加载、能存、能读回。副作用是上游改动不易发现回归——用 P0 的手动验收补 |
| **单文件 580KB 无构建** | 上线只用 min 版（gzip 80.6KB），与现导图同级 |
| **许可合规** | 保留 Apache-2.0 LICENSE、版权行，产物头部注明「基于 Weave 修改」 |
