> 目标：让 `E:\01-personal-blog`（渡鸦 NULL 博客）能"听歌"，音源来自 `E:\01-private-music`（Folia）。
> 已确认：**Folia 线上地址 `https://music.ravennull.work/`，部署在 Cloudflare Workers。**
> 本文只做可行性与改造方案，不含实现代码。

## 二、两边现状（写成方案的事实依据）

### 博客侧 `E:\01-personal-blog`

- Netlify 静态站：`[build] publish = "public"`，构建只做 `pnpm typecheck`，不打包前端（见 `netlify.toml`）。
- 后端是 Netlify Functions：`netlify/functions/*.ts`（`gallery`、`comments`、`life`、`upload`、`ai` 等 20 个），`/api/*` 由 `netlify.toml` 的 redirects 映射过去。
- 数据存储用 Netlify Blobs，封装在 `netlify/functions/_shared/blob.ts`（**注意：目前只暴露文本 KV 接口**，没有二进制流接口）。
- 首页是 4 个视图的 SPA 式切换：`public/index.html:94-99` 的 `#viewSwitch` 里 4 个 `view-btn`；`public/js/app.js:663` 的 `switchView()` 有硬编码白名单 `['home','blog','gallery','projects']`，禁用逻辑读 `settings.views`。
- 独立功能页走"单页 HTML"：`graph.html`、`mindmap.html`、`excalidraw.html`、`preview.html` 都是独立页面，`netlify.toml:19-23` 用 redirect 把 `/excalidraw` 映射到 `/excalidraw.html`。
- 样式：源文件在 `public/css/*.css`，由 `scripts/build-css.mjs` 合并成 `public/css/bundle.css` 并自动改写 `index.html` 里的 `?v=hash`。
- 响应头：`netlify.toml` 只配了缓存头，**没有全局 CSP、没有 X-Frame-Options** —— 博客自己既能被嵌、也不限制嵌别人。
- 已有 CORS 白名单机制：`netlify/functions/_shared/cors.ts`（`ALLOWED_ORIGIN` 环境变量，默认 `https://ravennull.work`）。

### Folia 侧 `E:\01-private-music`

- 独立应用：`package.json` 要求 **Node ≥ 24**，Vite 构建，`main` 是 Electron 入口；桌面端 + Web 端两套形态。
- 后端依赖外部音乐 API：`NeteaseCloudMusicApiEnhanced`（需自建实例，配 `VITE_NETEASE_API_BASE`）、可选 `VITE_KUGOU_API_BASE`、QQ 音乐走内置 serverless 入口 `/api/qq`（配 `QQ_SESSION_SECRET`）。
- 线上形态：Cloudflare Workers，配置在 `wrangler.jsonc`（`/api/*` 走 `run_worker_first`，静态资源 `not_found_handling: single-page-application`，入口 `worker/index.ts`）。
- **iframe 可行性已实测（2026-10-31）**：`GET https://music.ravennull.work/` 返回 `200`，响应头只有 Cloudflare 默认头（`server: cloudflare`、`cache-control`、`cf-cache-status: HIT` 等），**没有 `X-Frame-Options`，也没有 `Content-Security-Policy`**；源码 `src/`、`worker/`、`api-ts/` 里也搜不到 `window.top !== window.self` 之类的防嵌跳出逻辑 —— **可以直接 iframe 嵌入，Cloudflare 侧无需任何改动**。
- 提供两套对外接口：
  - **Stage API**（`http://127.0.0.1:32107`，需 Bearer token，含 WS `STATUS`/`TRACK_CHANGED`/`PLAYBACK_UPDATED` 推送，可搜索、点播、控队列）——只在本机回环地址监听。
  - **Electron 歌词接口**（`GET http://127.0.0.1:32109/v1/lyric`）——同样只在本机。
- 播放依赖**访客自己的登录态**：前端把各平台 cookie 存在浏览器本地，不集中存在服务端。

## 三、各方案详解

### 方案 A：导航入口跳转（推荐第一步）

改 `public/index.html:94-99` 的视图条，**不要**新增 `view-btn`（那会牵动 `switchView` 白名单、`moveIndicator`、视图显隐等一连串逻辑），而是加一个纯外链：

```html
<a class="view-btn view-btn--link" href="https://music.ravennull.work/" target="_blank" rel="noopener noreferrer">音乐</a>
```

- 样式可直接复用 `.view-btn`，必要时补一条 `.view-btn--link { text-decoration: none; }` 到 `public/css/renewal.css`，然后 `pnpm build:css`。
- 想更轻：只在 `projects` 视图里加一张"项目卡片"指向 Folia，改 `public/js/app.js` 的项目数据即可。
- 优点：不动构建、不动函数、零风险，改坏了也只是个链接。

### 方案 B：音乐作为首页第 5 个视图（✅ 已落地并实测）

> **实现状态**：已完成，真实 Chrome 实测通过。
> 最初做成独立页 `music.html`，但与另外四个视图比起来"像跳出去开了个外站"，于是改成**首页第 5 个视图**：点「音乐」原地切换、不跳页，`/music` 旧链接 301 到 `/#music`。独立页已删除。

做法：在 `index.html` 的 `.main-content` 里加第 5 个 `.view` 区块，和 `view-home`/`view-blog` 同级；`app.js` 的 `switchView` 白名单加入 `music`，视图显隐、滑块、入场动画全部沿用原有机制。

**1. 博客侧**：`netlify.toml` 里 `/music` 改成 `301 → /#music`（旧链接继续可用），真正的播放器在首页视图里（见下方落地清单）。

**2. Folia 侧：已实测无需改动。**

`https://music.ravennull.work/` 当前没有 `X-Frame-Options` / `frame-ancestors`，直接嵌就行。

（可选，防御性加固）如果你担心以后某次部署加上限制，可以在 `worker/index.ts:67` 的 `return env.ASSETS.fetch(request)` 处包一层，给 HTML 响应补一条白名单：

```ts
const response = await env.ASSETS.fetch(request);
const headers = new Headers(response.headers);
headers.set("Content-Security-Policy", "frame-ancestors 'self' https://ravennull.work https://*.ravennull.work");
return new Response(response.body, { status: response.status, headers });
```

注意：这条只是"声明允许谁嵌"，不是必须项；加了之后如果博客域名变了要同步改，所以**不急着加**。

**3. 视图里的 iframe**（现在位于 `index.html` 的 `#view-music`）：

```html
<iframe src="https://music.ravennull.work/"
        allow="autoplay; fullscreen; clipboard-write; encrypted-media; picture-in-picture"
        loading="lazy" referrerpolicy="strict-origin-when-cross-origin"></iframe>
```

必须注意的坑：

- **不要加 `sandbox` 属性**：Folia 依赖 localStorage/IndexedDB 存登录态和播放设置，sandbox 会让它直接报错。
- **autoplay**：浏览器要求用户手势后才能响。所以"进博客自动放歌"做不到，必须是访客自己点 Folia 界面里的播放。
- **登录态是第三方存储**：Safari/Chrome 的第三方存储分区会隔离 iframe 里的 localStorage，访客需在 iframe 内单独登录一次各音乐平台（这就是 Folia 的正常流程，不算故障）。
- **移动端体验**：Folia 是全屏沉浸式歌词 UI，塞进 iframe 后高度受限、滚动嵌套、iOS 键盘/地址栏会导致布局抖动。建议 iframe 用 `min-height: 100dvh` 且页面隐藏博客自身的滚动条，或干脆移动端（`max-width: 768px`）降级为方案 A 的跳转按钮。
- **性能**：Folia 是个大 SPA，iframe 首屏较重，务必 `loading="lazy"`。

#### 踩过的坑（都已在代码里注释）

1. **iframe 初始 `src` 必须是 `about:blank`**：留空会被解析成本页地址，导致无限递归加载。
2. **不能加 `sandbox`**：Folia 靠 localStorage 存登录态与播放设置，sandbox 会让它初始化即报错。
3. **遮罩不能等 iframe 的 `load`**：Folia 冷启动实测 `load` 要 20s+，一直盖着自家遮罩等于让用户盯转圈。现在改成「6 秒后无条件让位给 Folia 自己的启动动画」，并用 `fetch(首页, {mode:'no-cors'})` 探活成功时提前让位。
4. **别对慢加载喊失败**：探活成功即取消"加载失败"计时；只有 20s 内既无探活也无 `load` 才提示，并给「重试 / 新窗口打开」。
5. **手机默认降级**：≤768px 不加载 iframe，展示「打开播放器 / 还是在这个页面里听」；选后者写 localStorage 记住。
6. **音乐视图要脱离 `main-content` 的盒子**：`body.view-music-active` 时那条 `max-width:1200px` + `padding:32px 28px 72px` 会把 iframe 挤在中间，必须显式盖掉（`css/music.css`）。
7. **视图从 `display:none` 切回来要重新量高度**：隐藏时量到 0，`MusicView.onShow()` 里按 `scrollArea.clientHeight` 重设 iframe 高度。
8. **改 `app.js` 必须同步换 `?v=`**：`netlify.toml` 把 `/js/*` 设成 `max-age=31536000, immutable`。这次就踩了——只改内容没换版本号，线上 `cf-cache: HIT` 一直返回旧 app.js，音乐按钮点了没反应。改完 app.js 记得把 `index.html` 里的 `js/app.js?v=` 一起改。

#### 已知限制

- Folia 首屏冷启动慢（实测 20s+ 才触发 `load`），首次进入不如直接开独立站点；已用「遮罩早让位 + `preconnect`/`dns-prefetch`」缓解。
- 未登录访客看到的是「还没有连接在线平台」的首页，需在 iframe 内自行登录各平台账号（Folia 自己的流程）。
- iframe 内登录态属第三方存储，Safari/Chrome 的分区策略会让它独立于博客主域：能正常用，但要单独登录一次。

### 方案 C：博客自建迷你播放器（不依赖 Folia）

如果你只是想"博客里能听自己的歌单"，这条路更可控，且和 Folia 完全解耦。

- 歌单：`public/data/music.json`（`public/data/` 已有 `recommendations.json` 的先例），结构如 `[{ "title", "artist", "cover", "src" }]`。
- 音频托管两条路：
  1. **直接静态托管**：放 `public/media/music/*.mp3`，Netlify CDN 自动支持 Range 请求，实现最省事，但音频会进 git 仓库，体积要注意。
  2. **Netlify Blobs**：复用 `netlify/functions/_shared/blob.ts`，但**必须扩展接口**——当前 `KVStore` 只有文本 `get/set`，音频需要 `arrayBuffer` 读取和流式响应（含 `Range` 处理）。属于需要新写一个 `netlify/functions/music.ts` 的工作量。
- 前端：`public/music.html` + `public/js/music-player.js`，用原生 `<audio>` + 播放列表 UI，封面可复用 `/api/image` 的图片压缩能力。
- 取舍：没有搜索、没有歌词、没有第三方曲库，只有你上传的曲子；换来的是完全自主、无跨域、无登录、iframe 无需考虑。

### 方案 D：博客 Functions 代理 Folia API（不推荐）

思路是 `netlify/functions/music.ts` 做网关，前端只跟自己的域名通信。问题在于：

- Folia 的 `/api/*` 是给它自己前端用的内部接口，不是对外契约，版本升级随时变（仓库版本 0.7.23，迭代很快）。实测 `/api/qq` 对 `HEAD` 返回 501、无 CORS 头，说明它压根没打算被第三方调用。
- 接口依赖各平台 cookie/登录，代理层需要存大量敏感会话状态。
- 遇到鉴权、防盗链、频控时排查成本很高。

只有在"必须让播放界面完全长成博客的样子"时才值得，建议排到最后。

### 方案 E：Stage API 本地联动（本地彩蛋）

Folia 桌面端开启 Stage Mode 后，`http://127.0.0.1:32107` 提供完整接口：`GET /stage/player/status`、`GET /stage/player/time`、`POST /stage/player/search`、`POST /stage/player/play`、`WS /stage/player/ws`。

可以做"博客页面实时显示我此刻在听什么"，甚至"从博客点歌推给 Folia 播放"。但有硬限制：

- Stage API 只监听回环地址，且需 Bearer token。
- 线上博客是 `https://ravennull.work`，从 https 页面请求 `http://127.0.0.1:32107` 属于**混合内容**，会被浏览器拦截；跨站私有网络访问（PNA）还有额外限制。
- 因此只在 **`netlify dev` 本地预览（http://localhost:8888）** 或 Electron 内嵌页面里可行 —— 定位成"自己玩的功能"，不要指望公网访客能用。

## 五、风险与边界（做之前必须知道）

1. **账号安全**：Folia 的播放能力建立在各音乐平台的登录上。公网博客里嵌 Folia，等于让访客用**他们自己的账号**登录（cookie 在各自浏览器里），不会泄露你的账号 —— 但反过来，**永远不要在 iframe/代理方案里硬编码你自己的 cookie 或 token**。
2. **版权与合规**：Folia 通过第三方 API 取流，公开站点大量嵌入存在被平台风控/下架的可能；方案 C 的自托管音频同样受版权约束。这张博客是公开域名，建议只做"入口"或"自持曲库"。
3. **第三方 API 稳定性**：Folia 的可用性强依赖 `NeteaseCloudMusicApiEnhanced` 实例和 QQ serverless 入口。Folia 挂了不能连累博客 —— 方案 A 天然满足；方案 B 要在 iframe 外加一层加载失败提示（`onerror` / 超时兜底）。
4. **混合内容**：博客是 https，任何 `http://` 资源（包括 `127.0.0.1`）都会被拦。方案 E 只适合本地。
5. **移动端**：全屏沉浸式播放器塞 iframe 天生别扭，务必留降级路径。
6. **构建一致性**：博客 CSS 是"源文件 → bundle"生成的，改样式必须走 `pnpm build:css`，否则 `bundle.css` 和 `?v=hash` 不更新，线上不生效。
7. **缓存**：Folia 首页带 `cache-control: public, max-age=0, must-revalidate`，改版后访客刷新即生效；但 iframe 内的 SPA 路由由它自己管，博客侧不需要额外处理。
